# 大学专场面试排队

## 1. 入口与数据

侧栏「候选人」之后的「面试排队」进入 `/interviews`。列表关联校招创建的全部大学专场，包括草稿、上线中和已结束的专场；点击创建或进入排队。每个专场分别提供专业面试官、文化面试官、HR 的分享和停止分享按钮，以及排队登记和大屏展示按钮。原有面试安排保留在 `/interviews/schedule`。

数据独立保存于 `interview_queues`、`interview_queue_entries`、`interview_queue_links`，每专场只有一个队列。排队登记不自动修改候选人简历或历史面试日程。专场创建了队列后不可删除，可结束专场；结束专场不终止队列，分享期限与停止分享单独控制。

## 2. 登记与个人查询

登记链接 `/interview-queue/register/:token` 无需登录，默认有效一天，可按分钟、小时或天设置（最短一分钟、最长一年）。登记采集姓名、学校、专业、当前在读学历、毕业年份、语言能力、联系电话、岗位方向、邮箱。学校默认关联专场的学校，毕业年份默认 **2027**，均可修改；语言可选择 CET-4、CET-6、雅思、托福或填写其他。

岗位方向可选择统一校招目录中当前有效的「现场面试」或「内推」岗位；现场岗位优先展示，添加「优先招聘」标签，同类保留原顺序。提交事务锁定岗位目录，再依据当前岗位类型写入阶段：现场进入 professional，内推进入 referral。停止招聘、移除或自填岗位均拒绝。点击「浏览校招岗位与 JD」可搜索、查看全部有效岗位的职责、要求、加分项、完整福利，薪资遵循专场设置。选择任一类型岗位后回填并返回，已填写信息保留。

查看 JD 从详情顶部开始阅读；点击「返回岗位列表」时恢复打开 JD 前的列表滚动位置和搜索条件，继续浏览刚才的岗位，桌面和手机一致。

九项草稿按登记链接分别保存在当前标签页 `sessionStorage`，查看 JD、返回和刷新可恢复；自填学校不会被专场默认值覆盖。成功提交后才清除草稿。关闭标签页或清理浏览器存储不保证保留尚未提交的草稿。

同一专场同一邮箱只能登记一次，重复登记提示邮箱找回。提交后签发 30 天学生查询会话，首次会话仅能查询本次登记；学生可直接退出，返回 `/interview-queue/mine` 查看阶段、面试结果及等待人数。内推记录显示「内推中」，不返回或展示排名（ahead=null），预计一周左右由相关部门联系；不展示专业／文化／定薪结果卡片。清理缓存或换设备后，用登记邮箱和六位验证码找回该邮箱的全部专场记录。验证码有效五分钟、60 秒重发间隔、每小时最多五次、最多五次错误尝试，并发消费只能成功一次。生产依赖已配置的 Resend 邮件服务，未配置时明确返回 424，不回显验证码。登记链接过期或停止分享后，已登记人员仍能找回自己的记录。

## 3. 分享与权限

### 登记与面试官二维码海报

后台「排队登记 · 二维码／链接」将当前登记链接显示为海报，可下载两种 PNG：群聊竖版 **1440×1920**、iPad 横屏版 **2160×1440**。两种海报均含大学专场名称、登记二维码、现场面试地址、北京时间有效期、五步现场说明和完整八步招聘流程（交纸质简历 → 登记排队面试 → 专业面试 → 文化面试 → 定薪 → 心理综合测评 → 发 Offer → 签三方协议）。专业面通过自动进入文化面排队，文化面通过进入定薪，沿用现有状态流转；测评、Offer、签约的后续安排由 HR 通知。

生成前可编辑现场地址，默认读取 CampusSession.location；点击「更新地址」保存到同一校招专场，后续重新打开仍使用保存地址（需要 interviews 可编辑权限）。空地址海报提示向现场 HR 确认；地址输入即时预览，修改保存后需重新下载已有图片。

可勾选「附加校招群二维码」并上传正方形 PNG／JPG／WebP（≤5MB、边长≤4096px）；海报同时显示登记码和群码，两者等大，分别标明用途。默认不附加；勾选未上传时暂停下载／展示，取消勾选仅保留登记码。群图片仅在当前窗口读取，内嵌 PNG 导出，不上传服务器或持久保存，关闭窗口后需重新选择。登记海报统一注明：只要交了纸质简历，如果本次线下没有面试到，后续 HR 会进行线上联系。下方另列内推说明：「内推岗位将安排内推，预计一周左右由相关部门人员联系。」并用放大、加粗、品牌色和下划线强调「纸质简历」四字。群聊竖版、iPad 横版及下载 PNG 均包含两条说明，完整招聘流程保留。

「iPad 横屏展示」放大海报，可隐藏工具栏；浏览器支持时可全屏。SVG 按容器完整缩放、不裁剪，适配近 3:2 和 4:3 的 iPad mini 横屏宽高比，竖屏和手机也可访问。PNG 使用同一 SVG 在浏览器本地生成，无外部图片／字体依赖，不会把登记凭证发送给额外的图片服务。iPad 可通过「打开生成的图片，长按保存」保存到相册，再横屏展示或由 HR 手动转发。

专业面试官、文化面试官、HR 的分享弹窗也使用同样的海报、两种尺寸、PNG 下载和 iPad 展示。每张保留完整八步招聘流程，突出当前角色所处环节，并提供对应五步操作指南：

| 海报 | 操作指南内容 |
| --- | --- |
| 专业面试官 | 按本队列序号单人计时、通过／待定二次确认、添加候选人建议、搜索岗位／浏览 JD 后修改方向、名单自动同步与全部待定来源 |
| 文化面试官 | 按本队列序号默认单人、勾选后群面共用计时及批量结果、通过进入定薪、逐人建议、名单自动同步与待定来源／历史建议 |
| HR 定薪 | 汇总核对全部人员、分配状态与当前队列序号，按席位叫号、待分配 Tab 分配及汇总转派／撤回、名单自动同步及内推 Tab、全量定薪人员及 8700／13.5 单人／批量修改、接受／放弃和建议、改岗位与待定重排、独立密钥永久删除排队记录 |

登记指南说明现场岗位登记排队、内推由相关部门后续联系；「优先招聘」「内推中」及排名规则仅在功能页面显示，不印入海报；停止招聘或移除的岗位不在公开目录展示。学生点击「刷新状态」获取进展；面试官／HR 的名单自动同步，网络异常时也可点击「刷新」重试。HR 海报的席位分配或无现场文化面说明仅替换第一步，保留改方向、待定重排及删除指南，避免配置变化后遗漏功能。

角色海报显示当前分享期限；仅密钥模式显示无固定到期时间，启用密钥时提示向分享人获取，海报不印访问密钥。文件名区分角色、专场和版式，登记海报文件名保持原样。

海报为静态图片，文案、地址、流程或席位名称变更后需重新下载；当前链接仍有效时可直接下载新版图片，无需点击「更新并生成新链接」。海报不会延长链接有效期。过期后不可继续下载；更新或停止分享会使旧海报二维码失效，更新链接后需重新下载和转发。校招专场首页／直接投递／智能匹配／电脑上传入口及 HR 岗位协作分享也复用海报导出／横屏能力，按入口展示独立页面指南和对应流程；学生投递海报不混用面试排队的纸质简历步骤。下载文件包含对应访问凭证，不应加入 Git 或运维日志。验证采用浏览器尺寸模拟与导出二维码解码，iPad 真机 Safari 的全屏和保存行为仍需现场核对。

### 面试官链接

面试官链接 `/interview-queue/share/:token` 无需工作台登录。浏览器标签页按分享角色显示「专业面试」「文化面试」或「定薪」，访问密钥验证页也使用对应名称。默认 **无密钥、有效三天**；可选择仅有效期、仅密钥或两者同时限制。启用密钥并留空时生成六位混合字母和数字，也可输入 6–64 位字母数字自定义密钥。密钥以 bcrypt 哈希和 AES 加密形式入库，只有可管理队列的后台用户能查看链接和密钥。

每个专场每个角色只有一个当前链接，更新配置会生成新链接并使原链接失效。停止分享立即使旧链接及已签发的面试官会话失效，每次读写都会检查激活状态、有效期和版本。专业、文化分享只能修改各自阶段；HR 可修改定薪资料，以及定薪／待定人员的岗位方向，并将待定人员重新排队；专业与文化角色不返回邮箱、薪资或薪资接受情况，专业／文化展示本阶段及该专场全部待定记录，HR 通过汇总及各 Tab 展示面试四阶段与内推；任一环节转入待定后，专业、文化、HR 三页同步显示，并可按「待定环节」筛选来源（专业面试／文化面试／定薪）。后台和大屏显示完整四个阶段。

工作台访问沿用 `interviews` 页面权限，VIEWER 仅查看，不能创建、分享或修改，列表也不返回分享凭证。匿名 JWT 的 audience 分别为 `interview-queue-share` / `interview-queue-student`，后台统一认证拒绝这两类凭证。

## 3.1 面试官席位与 HR 手动分配（2026-10-16）

每个专场的「面试官与流程设置」可添加专业／文化席位，并填写席位名称或面试官姓名，最多合计 40 个。可配置一名或多名专业面试官，文化面试官可为零、一名或多名；开启现场文化面试时至少有一名文化面试官。已有专场默认保留原来的单队列方式，保存席位设置后启用手动分配，已有人员先等待 HR 分配。

HR 分享页默认打开「汇总」，展示面试四阶段与内推的全部人员，包含当前阶段、分配状态（已分配／待分配／无需分配）及面试官，支持逐列筛选；在汇总逐人分配、转派或撤回专业／文化席位。「待分配专业面试官」「待分配文化面试官」两个 Tab 仅展示该阶段尚未分配席位的人员，人数也仅统计待分配记录，可多选或全选后分配；分配成功后自动从待分配名单移出，在汇总和对应面试官页面保留，撤回后重新进入待分配名单。进入下一阶段且清空席位时自动计入下一阶段待分配。定薪、待定、内推继续使用各自 Tab。HR 汇总和两个待分配 Tab、专业／文化面试官本阶段名单提供「排队序号」列，面试官当前单人卡也显示序号，文化群面勾选后保留每人的序号：专业／文化分别按当前面试官席位从 1 编号，未分配者按阶段单独编号，无席位旧专场按阶段编号。使用服务端按 phaseEnteredAt、createdAt、id 返回的顺序，在界面筛选前计算；筛选不重排，面试结果、分配／转派／撤回和重排后随名单自动更新。序号是当前队列位置（1 为队首），不是固定登记号码；定薪、待定、内推无面试排队序号，汇总显示「—」。可编辑后台及大屏沿用原有阶段 Tab 和全量阶段人数。只允许分配到与当前阶段一致的席位。同一个人同时只有一个席位，批量操作先校验全部人员版本，再原子提交；转派加入目标席位队尾，清除本阶段计时和文化群组，保留登记资料、已发生结果及历史建议。重复分配到原席位不重置计时。席位仍有人排队时不能删除或改为另一角色，需先转派或撤回分配。

专业／文化面试官海报弹窗可选择对应席位，分别下载带席位名称的海报。席位入口以当前角色链接加 `?station=<uuid>` 定位；同角色各席位共用角色链接的期限和访问密钥，更新或停止该角色分享会使全部对应旧海报失效。通用角色链接可选择 HR 指定的席位；打开后签发绑定队列、角色和席位的会话，每次读写校验当前配置。面试官只看到本席位当前阶段人员和全专场共用待定记录，不能通过修改动作请求操作其他席位。候选人按进入该席位的顺序面试，文化群面可在本席位内多选、共用计时。下一阶段流转及待定重排均清空原席位，等待 HR 重新安排。

关闭「现场安排文化面试官」后，可移除文化席位，支持单专业／多专业且无现场文化面的专场。登记海报、专业／HR 操作指南、登记表和学生记录统一提示：专业通过后等待 HR 联系线上文化面试及后续流程，不在现场继续排文化面。专业通过仍进入文化阶段，不跳过或伪造文化结果；线上面试安排好后，可再添加文化席位并由 HR 分配。学生已分配时显示面试官席位与本席位前方人数，未分配时显示「等待 HR 分配」，文化面改线上时显示待联系提示。

修改配置或席位后须重新下载、转发海报，已下载图片不会自动更新。该能力新增 `InterviewQueue.setup`（现场文化面开关及席位配置）和 `InterviewQueueEntry.stationId`，通过新增迁移 `20261016010000_interview_queue_stations` 实施；部署不会自动更改现有专场配置。上线前备份 PostgreSQL，回退镜像时保留新增字段与排队记录。

## 3.2 HR 删除排队人员（2026-10-16）

在大学专场「分享给 HR」弹窗中，单独设置或更新人员删除密钥，支持 6–64 位字母数字。它与分享访问密钥独立：更新删除密钥立即使旧删除密钥失效，不替换分享链接、不改变访问密钥或期限。未设置时默认禁止删除；保存后不回显，需由分享人单独告知 HR，忘记可重新设置。数据库仅保存 bcrypt 哈希，不向任何读取接口返回哈希、明文，也不印入二维码海报。

HR 分享页与可编辑后台在专业、文化、定薪、待定四个阶段提供逐人「删除人员」。确认框展示姓名、学校及所属专场，每次都必须输入删除密钥。成功后永久删除该专场排队记录、面试结果和关联建议；校招候选人资料、原始简历及其他专场记录保留。被删除者不再出现在该专场的大屏、面试官队列或学生记录中，面试官／HR／后台／大屏自动同步，学生点击刷新获取最新状态；同邮箱可重新登记。

服务端在同一专场事务锁内重新验证角色分享、当前删除密钥及人员 updatedAt；分享停止／过期、旧会话、跨专场或旧人员版本均拒绝。专业／文化、学生和只读后台不能删除或设置密钥。删除接口按后台账号／HR 分享链接每分钟最多 10 次，换同链接会话不重置计数。仅空白或错误密钥不会删除人员；失败原因保留在确认框，密钥输入每次提交后清空。

新增可空字段 `InterviewQueue.deletionKeyHash`，迁移 `20261016020000_interview_queue_deletion_key`；不修改既有队列的默认权限。发布前备份数据库，回滚镜像可停用入口并保留哈希字段；已经删除的记录不能通过回退镜像恢复，需从备份恢复。

## 4. 面试四阶段与内推

| 操作 | 结果 | 下一阶段 |
| --- | --- | --- |
| 专业面试 | 通过 | 文化面试 |
| 专业面试 | 待定 | 待定 |
| 文化面试 | 通过 | 定薪 |
| 文化面试 | 待定 | 待定 |
| 定薪 | 接受 | 保留定薪并标记接受 |
| 定薪 | 放弃 | 待定 |

专业面试按进入阶段的时间排队，展示当前人员和后续人员；每人建议十分钟，可修改岗位方向。文化面试默认同样展示当前单人和后续人员，每人建议十分钟，可直接开始计时、二次确认通过或待定；只有勾选人员／全选后才显示群面和「所选人员通过／待定」，一组共用计时，建议五至十分钟。可取消选择恢复单人面试，已计时组仍可重新进入继续操作。计时开始时间和群组保存在数据库，刷新可进入已计时组继续；复用 `LiquidLoader` 波浪球，十分钟充满且变红，禁止重复重置计时。

岗位方向使用页面内可搜索菜单，展开显示全部有效校招岗位；支持键盘上下选择、Enter 选定和自行填写。专业面试官可改当前及后续专业面试人员，HR 可改定薪及待定人员，后台沿用工作台权限。点击「浏览校招岗位与 JD」可看完整职责、要求、加分项、福利；现场／内推均明确标记，面试官与 HR 可选择两类岗位（学生登记时按所选岗位类型分流）。浏览返回保留当前选择，JD 返回列表保留搜索和滚动位置；浏览详情按当前角色会话鉴权，薪资遵循专场公开设置，不返回内部评价模型。

专业、文化结果和岗位修改需二次确认。HR 默认基础薪资 **8700**、基数 **13.5**；可逐人或多选/全选修改基础薪资、基数、接受/放弃，仅勾选字段才应用。确认窗口明确列出人员与修改值。待定页保留实际已发生的结果，未进行的阶段显示「—」。

### 待定重新排队

HR 和可编辑后台在待定表「操作」列点击「重新排队」，选择专业面试或文化面试，二次确认后进入该阶段队尾；同一专场串行写入，并在事务内取目标阶段末尾时间，确保同毫秒重排仍按队尾顺序加入。三角色与大屏自动同步最新状态；学生点击「刷新状态」获取进展。

重排保留登记资料、岗位方向、基础薪资／基数及历史建议；专业面重排清空专业及文化结果、两段计时／群组和薪资接受状态。文化面重排清空文化结果／计时／群组及薪资接受状态；已真实通过的专业结果及计时保留，原专业待定会清除，不伪造通过。只允许待定人员逐人重排；旧版本、跨专场、只读账号和非 HR 分享拒绝操作，分享停止／过期即时失效。

### 面试建议

专业、文化单人面试卡和人员表格、HR 定薪表格提供「添加建议」。群面时逐人填写，保存后保留当前勾选。建议按条追加，保存正文、添加角色及时间；后续面试阶段和后台可查看此前建议，待定页也可查看。单条 1–5000 字，保存不改变面试结果、排队顺序或计时。

建议写入当前角色对应阶段，后台沿用工作台权限；只读账号和分享页待定记录只能查看。角色由后台认证确定，不能由表单指定。每次写入仍在队列事务锁内校验分享有效性和人员版本。学生登记／查询接口不返回内部建议，大屏不展示建议。

## 5. 并发与大屏

后台队列、三类角色分享页及大屏在可见时约每三秒错峰检查轻量版本接口；版本改变后只刷新一次对应名单，未变化不请求人员／岗位列表。滚动部署遇到版本检查接口 404 时，自动回退到既有条件读取接口，保持名单同步。页面隐藏时暂停，恢复可见立即检查；网络和限流失败从五秒开始退避，最长约三十秒，权限失效停止。手动刷新与当前读取串行，写入时遇到进行中的旧读取会补一次强制刷新，防止新状态被漏掉。刷新不重载页面，保留当前 Tab、筛选、编辑框和输入，已离开阶段的勾选自动移除，提交仍使用人员版本校验。学生页继续通过「刷新状态」按钮更新。队列 `revision` 配合条件读取，未变化不重复返回列表；每次登记、计时、流转或分享操作递增版本。同一专场写入用数据库事务串行提交，人员 `updatedAt` 乐观检查；旧版本、跨专场、错误阶段或重复选择返回 409/400，不部分写入。分享撤销与操作使用同一事务锁，写入前再次验证链接，防止失效凭证落盘。

大屏 `/interview-queue/screen/:sessionId` 在工作台认证和页面权限内，独立于侧栏布局；深色背景、大号表格、实时时钟和全屏按钮。五个 Tab 为专业面试、文化面试、定薪、待定、内推；HR 分配或其他页面修改结果后，自动同步最新阶段。大屏只展示结果，修改在后台或对应分享页完成。每列可搜索内容、勾选多个值、全选或清除筛选，列间按 AND 组合。手机表格在自身容器内横向滚动，页面不会横向溢出。

## 6. 部署与回滚

新增迁移 `20261015000000_interview_queues`；面试建议另由 `20261015030000_interview_queue_suggestions` 新增关联表，不修改历史迁移。上线前备份 PostgreSQL；部署按既有 `prisma migrate deploy` 执行新增表。回滚前后端到上一镜像即可停用新入口，新增表保留登记和结果，原有面试日程与校招数据不受影响。不要用删表回滚丢弃排队记录。

开发验证：`cd server && npm test`、`cd web && npm run build`。真实 PostgreSQL 隔离库验证迁移、登记/流转、群面共同计时、批量定薪、版本冲突、角色隔离、分享撤销、邮箱找回及验证码重放；浏览器检查桌面及 390px 手机页面。

### 内推列表

HR 分享页、工作台和大屏提供「内推」Tab，展示登记资料及联系方式，支持逐列筛选；不参加现场计时、席位分配或薪资流程。专业／文化面试官名单不包含内推记录。HR 原有独立密钥删除权限同样适用于内推登记。既有记录阶段保留，不按后来修改的岗位类型自动流转。校招学生岗位列表、JD、匹配结果与排队选岗统一突出现场岗位「优先招聘」。
