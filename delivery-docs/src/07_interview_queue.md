# 大学专场面试排队

## 1. 入口与数据

侧栏「候选人」之后的「面试排队」进入 `/interviews`。列表关联校招创建的全部大学专场，包括草稿、上线中和已结束的专场；点击创建或进入排队。每个专场分别提供专业面试官、文化面试官、HR 的分享和停止分享按钮，以及排队登记和大屏展示按钮。原有面试安排保留在 `/interviews/schedule`。

数据独立保存于 `interview_queues`、`interview_queue_entries`、`interview_queue_links`，每专场只有一个队列。排队登记不自动修改候选人简历或历史面试日程。专场创建了队列后不可删除，可结束专场；结束专场不终止队列，分享期限与停止分享单独控制。

## 2. 登记与个人查询

登记链接 `/interview-queue/register/:token` 无需登录，默认有效一天，可按分钟、小时或天设置（最短一分钟、最长一年）。登记采集姓名、学校、专业、当前在读学历、毕业年份、语言能力、联系电话、岗位方向、邮箱。学校默认关联专场的学校，毕业年份默认 **2027**，均可修改；语言可选择 CET-4、CET-6、雅思、托福或填写其他。

岗位方向只能选择统一校招目录中当前有效且标为「现场面试」的岗位，提交时后台再次校验。点击「浏览校招岗位与 JD」可在登记页内查看全部有效校招岗位，包括内推；内推明确提示「内推，非现场面试」，不能选作排队方向。JD 展示职责、要求、加分项、完整福利，薪资遵循关联专场的学生端展示设置。选择现场岗位后回填方向并返回表单，其余填写内容保留。

九项草稿按登记链接分别保存在当前标签页 `sessionStorage`，查看 JD、返回和刷新可恢复；自填学校不会被专场默认值覆盖。成功提交后才清除草稿。关闭标签页或清理浏览器存储不保证保留尚未提交的草稿。

同一专场同一邮箱只能登记一次，重复登记提示邮箱找回。提交后签发 30 天学生查询会话，首次会话仅能查询本次登记；学生可直接退出，返回 `/interview-queue/mine` 查看阶段、面试结果及等待人数。清理缓存或换设备后，用登记邮箱和六位验证码找回该邮箱的全部专场记录。验证码有效五分钟、60 秒重发间隔、每小时最多五次、最多五次错误尝试，并发消费只能成功一次。生产依赖已配置的 Resend 邮件服务，未配置时明确返回 424，不回显验证码。登记链接过期或停止分享后，已登记人员仍能找回自己的记录。

## 3. 分享与权限

### 登记二维码海报

后台「排队登记 · 二维码／链接」将当前登记链接显示为海报，可下载两种 PNG：群聊竖版 **1440×1920**、iPad 横屏版 **2160×1440**。两种海报均含大学专场名称、登记二维码、北京时间有效期、五步现场说明和完整八步招聘流程（交纸质简历 → 登记排队面试 → 专业面试 → 文化面试 → 定薪 → 心理综合测评 → 发 Offer → 签三方协议）。专业面通过自动进入文化面排队，文化面通过进入定薪，沿用现有状态流转；测评、Offer、签约的后续安排由 HR 通知。

「iPad 横屏展示」放大海报，可隐藏工具栏；浏览器支持时可全屏。SVG 按容器完整缩放、不裁剪，适配近 3:2 和 4:3 的 iPad mini 横屏宽高比，竖屏和手机也可访问。PNG 使用同一 SVG 在浏览器本地生成，无外部图片／字体依赖，不会把登记凭证发送给额外的图片服务。iPad 可通过「打开生成的图片，长按保存」保存到相册，再横屏展示或由 HR 手动转发。

海报不会延长登记链接有效期。过期后不可继续下载；更新登记链接会使旧海报二维码失效，需重新下载和转发。下载文件包含登记凭证，不应加入 Git 或运维日志。验证采用浏览器尺寸模拟与导出二维码解码，iPad 真机 Safari 的全屏和保存行为仍需现场核对。

### 面试官链接

面试官链接 `/interview-queue/share/:token` 无需工作台登录。默认 **无密钥、有效三天**；可选择仅有效期、仅密钥或两者同时限制。启用密钥并留空时生成六位混合字母和数字，也可输入 6–64 位字母数字自定义密钥。密钥以 bcrypt 哈希和 AES 加密形式入库，只有可管理队列的后台用户能查看链接和密钥。

每个专场每个角色只有一个当前链接，更新配置会生成新链接并使原链接失效。停止分享立即使旧链接及已签发的面试官会话失效，每次读写都会检查激活状态、有效期和版本。专业、文化、HR 分享只能修改各自阶段；专业与文化角色不返回邮箱、薪资或薪资接受情况，各角色展示本阶段和由本角色产生的待定记录。后台和大屏显示完整四个阶段。

工作台访问沿用 `interviews` 页面权限，VIEWER 仅查看，不能创建、分享或修改，列表也不返回分享凭证。匿名 JWT 的 audience 分别为 `interview-queue-share` / `interview-queue-student`，后台统一认证拒绝这两类凭证。

## 4. 四阶段流程

| 操作 | 结果 | 下一阶段 |
| --- | --- | --- |
| 专业面试 | 通过 | 文化面试 |
| 专业面试 | 待定 | 待定 |
| 文化面试 | 通过 | 定薪 |
| 文化面试 | 待定 | 待定 |
| 定薪 | 接受 | 保留定薪并标记接受 |
| 定薪 | 放弃 | 待定 |

专业面试按进入阶段的时间排队，展示当前人员和后续人员；每人建议十分钟，可修改岗位方向。文化面试支持多选群面，一组共用计时，并批量确认通过或待定，建议五至十分钟。计时开始时间和群组保存在数据库，刷新可进入已计时组继续；复用 `LiquidLoader` 波浪球，十分钟充满且变红，禁止重复重置计时。

专业、文化结果和岗位修改需二次确认。HR 默认基础薪资 **8700**、基数 **13.5**；可逐人或多选/全选修改基础薪资、基数、接受/放弃，仅勾选字段才应用。确认窗口明确列出人员与修改值。待定页保留实际已发生的结果，未进行的阶段显示「—」。

## 5. 实时、并发与大屏

后台、分享和学生页每两秒更新。队列 `revision` 配合条件读取，未变化不重复返回列表；每次登记、计时、流转或分享操作递增版本。同一专场写入用数据库事务串行提交，人员 `updatedAt` 乐观检查；旧版本、跨专场、错误阶段或重复选择返回 409/400，不部分写入。分享撤销与操作使用同一事务锁，写入前再次验证链接，防止失效凭证落盘。

大屏 `/interview-queue/screen/:sessionId` 在工作台认证和页面权限内，独立于侧栏布局；深色背景、大号表格、实时时钟和全屏按钮。四个 Tab 为专业面试、文化面试、定薪、待定；结果在其他页面修改后，人员自动移入目标阶段。大屏只展示结果，修改在后台或对应分享页完成。每列可搜索内容、勾选多个值、全选或清除筛选，列间按 AND 组合。手机表格在自身容器内横向滚动，页面不会横向溢出。

## 6. 部署与回滚

新增迁移 `20261015000000_interview_queues`，不修改历史迁移。上线前备份 PostgreSQL；部署按既有 `prisma migrate deploy` 执行新增表。回滚前后端到上一镜像即可停用新入口，新增表保留登记和结果，原有面试日程与校招数据不受影响。不要用删表回滚丢弃排队记录。

开发验证：`cd server && npm test`、`cd web && npm run build`。真实 PostgreSQL 隔离库验证迁移、登记/流转、群面共同计时、批量定薪、版本冲突、角色隔离、分享撤销、邮箱找回及验证码重放；浏览器检查桌面及 390px 手机页面。
