# 飞书机器人：旧简历入库退役与自动定薪切换

更新：2026-10-23。新实现已完成本地验证，通过既有CI/CD发布。原入库方案为历史设计，当前待交付行为以本文和[校招自动定薪说明](09_campus_salary.md)为准。

## 当前实现

复用现有飞书应用、lark-cli长连接、消息资源下载和 `/api/feishu/card-callback` 回调。管理员在「校招定薪」配置启用的群、实际租户、合同签署地、录用岗位和授权账号。群内发送简历后，直接生成定薪建议、条件情景及待补材料，不再要求关联JD或点击解析。

连续发送10份独立简历文件时，监听器限制3份并行下载并提交，后台使用现有AI worker队列逐份处理，回显回复到各自原消息。单份失败不阻塞其他文件。

## 已废除的机器人行为

- 不再通过公开上传token创建Candidate，不再关联或新建Job。
- 不再进行JD匹配、综合分评估或自动创建ShareLink。
- 旧卡片的关联、查看、新建JD与解析按钮统一返回停用提示。
- 旧解析完成通知 `notifyCandidateReady` 保留兼容导出但无发送/创建分享链接副作用。
- 原网站招聘收件箱、候选人解析、人工分享等功能保留，历史招聘数据不删除。

独立定薪表保存原始事实、人工补充、录用上下文、政策版本及每次测算历史。汇总默认显示当前有效简历；仅同名不自动合并，同人可靠匹配后采用最新发送文件，旧版可在详情中查看。

## 配置变化

`LARK_UPLOAD_TOKEN` / `UPLOAD_TOKEN` 不再用于监听器。后端、worker与监听器复用现有 `LARK_APP_SECRET`，内部请求使用时间戳、HTTP方法、路径和完整正文的HMAC签名。凭证只从环境读取，不能写入代码或文档。

`LARK_TENANT_KEY` 仅为事件缺少租户时的回退，必须与群配置和卡片回调的实际租户一致。默认 `default` 用于两端均无租户字段的测试，不应替代真实租户。

本轮未更改真实应用权限、未发群消息、未部署。新迁移与服务切换方式见[定薪说明](09_campus_salary.md)，监听器运行示例见 `tools/lark-ingest/README.md`。
